Privacy

What leaves, and what doesn’t.

Written to be checkable rather than reassuring. Where something is not private, this page says so in the same size type as everything else.

Last updated 14 August 2026 Applies to Meram 2.0 beta and to meram.app

The short version

Meram has no server. There is no account, no login and no product analytics. Your dictations, your dictionary and your settings live in files on your own machine. The one thing that leaves is your audio — sent to the transcription provider you chose, using your key — plus the transcript, if you switch on cleanup or translation. Nothing is sent to us, because there is nowhere for it to be sent.

There is no fully offline mode today. On-device transcription exists in the source but is deliberately switched off until it can be packaged and verified, so “100% offline” is not a claim this product is entitled to make yet. When that changes, this paragraph changes first.

What Meram sends

WhatWhere it goesWhen
Recorded audio Groq or OpenAI — whichever you selected, with your key Every dictation. This is the transcription request itself.
The transcript, plus a short biasing prompt The same transcription provider The biasing prompt carries terms from your own history and dictionary, capped in length.
The transcript and the applicable context The chat provider you configured Only when AI cleanup, tone matching or translation is enabled.
Screen context Whichever provider the request is going to Only if you turn screen grounding on. It is off by default.
An update check GitHub On launch, unless you turn automatic updates off. GitHub sees your IP address, as any download does.
Crash reports Sentry — only in a build compiled with a DSN Not enabled by default. If a build you install has it, exception metadata can be sent.

Those providers have their own terms and their own retention policies, and they apply to your account with them rather than to anything of ours. Choosing a provider is choosing whose privacy policy governs your audio.

What stays on your machine

  • History. Every dictation, in a local SQLite database, along with provider and model names, timing, and transcription-prompt diagnostics.
  • Dictionary and snippets. Yours, local, editable and deletable.
  • Settings. A JSON file you can open and read.
  • Audio recordings. Not kept, unless you switch on “keep audio” — then they are written under the app data folder and stay there until you delete them.

Your API key

Your key is stored through the operating system’s own encrypted storage (Electron’s safeStorage) when the OS provides it. Where it does not, a compatibility path can store the value in plain text — that is a real limitation and it is written here rather than left in a source file.

There is also a second copy on disk: meram-settings.json.bak, rewritten after every successful save. It exists because the settings library silently replaces a file it cannot parse with defaults, taking every key, hotkey and dictionary entry with it. The backup carries exactly the same protection as the live file — no more, no less.

The key is sent only to the provider it belongs to. It never reaches us; we operate no service that could receive it.

Things that are off unless you turn them on

  • Screen context. Off by default. When on, what it reads is best-effort and ephemeral unless something derived from it lands in history.
  • Clipboard history. Off by default. When on, it keeps up to 200 entries locally, skips formats that password managers mark as do-not-persist, and skips Meram’s own writes. No clipboard detector can promise to recognise every secret, which is why it is off. Disabling it purges what was stored.
  • Wakeword. Off by default. When on, it holds a second, permanently live microphone stream for as long as it is enabled — separate from the dictation recorder. The capsule shows a microphone badge for the entire time that stream is open, because a permanently open microphone should be visible.
  • Semantic memory. Disabled entirely in this release. No vectors are generated or searched.

Password fields

When the focused control is a password field — or the target is elevated, or macOS Secure Event Input is active — Meram writes nothing at all. Not into the field, and not onto your clipboard as a fallback. A dictation that is lost is a much smaller problem than a password manager’s field receiving speech, or a secret sitting in a clipboard you forgot about.

What this website sees

No analytics, no tracking pixels, no cookies, no consent banner to dismiss. The fonts are served from this domain rather than from a font CDN. Two things are worth naming anyway:

  • GitHub. This site asks GitHub’s public API for the latest release so the download buttons point at a real file. That request comes from your browser, so GitHub sees your IP address and user agent.
  • Hosting logs. The site is served by Vercel, which keeps ordinary request logs — IP address, user agent, the URL requested — as any web host does.

The microphone demo on the home page is exactly what it says it is: the audio goes to a Web Audio analyser in your own tab, drives the light thread, and is never recorded, uploaded or connected to the audio output. The page holds no API key and cannot transcribe anything. Close the tab, or press the release button, and the stream is stopped.

Deleting your data

There is no account to close and no request to file, because we hold nothing. Delete individual dictations from History, clear the lot from Settings, or remove %APPDATA%\Meram and every trace of your use is gone. Data already sent to a transcription provider is governed by your relationship with that provider.

Children

Meram is not directed at children under 13 and collects nothing from anyone.

Changes

When the product’s behaviour changes, this page changes with it — and where a change makes something less private than it was, it will be described here in plain terms rather than absorbed into a version bump.

The honest summary

Your audio goes to one company you picked, using a key you own. Everything else stays on your disk. There is no hosted mode, no account, and no offline mode — yet.

Sub-processors

Groq or OpenAI — transcription, your key.
Your chat provider — cleanup and translation, when enabled.
GitHub — downloads and update checks.
Vercel — this website.
