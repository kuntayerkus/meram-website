About

Made by one person,
and the list to prove it.

Meram is built by Grio Works — Kuntay Erkuş, in Türkiye. Not a team, not a platform, and not a company that can afford to be vague about what its software does.

The name

Meram is a Turkish word for the thing you are trying to say — your intent, the meaning underneath the sentence. Meramını anlatmak is to get your point across. It is the exact distance a dictation app has to travel: not from sound to characters, but from what you said to what you meant.

It was called Speechy first. That name described the input. This one describes the output, which is the harder and more honest thing to be judged on.

Why it exists

Because dictation in Turkish is badly served, and because the tools that do exist ask you to leave the thing you were doing. A dictation product that opens a window has already lost — the value is entirely in not breaking your attention, which means the interface has to be a shortcut and a two-hundred pixel capsule, and nothing else.

Most of the engineering is not in the transcription, which is a paid API call. It is in the parts nobody demos: proving the window you were in is still the window you are in, refusing to type into a password field, keeping the fricatives that Turkish needs and that every noise suppressor eats, and never losing a sentence you already said out loud.

The rule this site is written under

The repository carries a document that separates code that exists from behaviour proven in a packaged build. Every claim on this website is drawn from it. When that document and the running software disagree, the software wins and the document gets corrected — never the other way round.

Core is part of the hotkey → speak → safe paste promise. Beta means the code is there and the platform matrix is not finished. Neither word means “tested on your hardware”, because your hardware is the one thing nobody can test from here.

Deliberately switched off

  • Noise suppression. It eats the fricatives that carry meaning in Turkish. Off is the correct setting, not a missing feature.
  • On-device Whisper. Written, and disabled until it can be packaged with pinned checksums and a verification corpus. Until then there is no offline mode and this site does not claim one.
  • The mock transcription provider. It produces demo text, not speech recognition — leaving it selectable would leave a path that looks like a successful setup and is not.
  • Semantic memory. Its runtime dependency was removed pending a maintained replacement and a fresh privacy review.
  • Select-less voice editing and its undo. Off until a rollback can be verified transactionally. An undo that cannot prove what it undid is worse than no undo.

What has to be true before anything is called stable

  1. A signed Windows installer, and a signed, notarized macOS build.
  2. A real update rehearsal: install the previous public build, update to the new one, on both platforms.
  3. A manual matrix across browsers, office suites, chat apps, Electron editors, native fields, elevated targets, multiple monitors and non-US keyboards.
  4. Published latency, paste-success and crash-free numbers — measured, not estimated.
  5. Keyboard-only navigation, screen-reader labels, contrast and reduced-motion, verified rather than assumed.

Until those pass, “2.0” is a version number in a repository and an implementation milestone. It is not a claim of production readiness, and you should hold this project to that sentence.
